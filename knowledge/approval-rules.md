# Approval rules

Approvals apply to a defined stage, artifact revision and target scope. Store a redacted
authority reference, not a transcript, account name or personal identity. An agent cannot
supply its own user approval. Previously granted authorization remains valid within scope.

Substantial changes to approved objects need explicit revision authorization and a
checkpoint. Reopening invalidates dependent stage evidence. Minor authorized corrections
still need a change log and refreshed evidence; an unchanged object can remain protected.
No automatic deletion, remeshing, rebuild, destructive modifier application or publication.

`Workflow` enforces cooperative stage transitions and guarded adapter operations. A local
JSON journal cannot authenticate who wrote an approval, and direct Blender/MCP access can
bypass BMA. Do not describe this mechanism as a security sandbox.
